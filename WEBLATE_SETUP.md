# Weblate setup for `pl_ZW` (seeded from `pl_PL`)

Generated by assemble_l10n_repo.py. Menu names vary a little between Weblate versions.

1. **Admin -> Languages**: add `pl_ZW` (name, plural formula copied from `pl_PL`).
2. Create a project, then in each component use **File format: gettext PO file** and
   **Language code style: POSIX with underscore**.

## Core
Create ONE component by hand first (it becomes the 'main' component):

    name:                     core-admin
    file mask:                core/po/*/admin.po
    template for new transl.: core/po/pot/admin.pot

Then add the **Component discovery** add-on to it:

    match:             core/po/(?P<language>[^/]+)/(?P<component>[^/]+)\.po
    name template:     core-{{ component }}
    base file:         core/po/pot/{{ component }}.pot
    language filter:   ^pl_ZW$

## Extensions
Add a second discovery add-on (same repository, so it reuses the main component):

    match:             extensions/po/(?P<component>[^/]+)/(?P<language>[^/]+)/(?P=component)\.po
    name template:     ext-{{ component }}
    base file:         extensions/po/{{ component }}/pot/{{ component }}.pot
    language filter:   ^pl_ZW$

## Add-ons worth enabling
- Update PO files to match POT (msgmerge)
- Ensure a consistent set of languages across components
- Customize gettext output (keep line wrapping stable to avoid noisy diffs)

## Keeping up with upstream
Re-run `assemble` (same arguments), commit and push; Weblate pulls the new template and
base-language fills. Translations already edited in the fork are never overwritten.

## Deploying
`build-mo --repo . --locale pl_ZW` writes `dist/l10n/pl_ZW/LC_MESSAGES/*.mo`. Compare with an
existing locale folder under your `[civicrm.l10n]` directory to confirm where extension
.mo files belong on your install.
